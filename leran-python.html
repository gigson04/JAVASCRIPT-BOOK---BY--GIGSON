Front Matter

Preface: How to Use This Book

Python is not learned by reading. It is learned by writing. You can read every page of this book and still not know Python if you never open an editor, make mistakes, and fix them. That is the uncomfortable truth most beginner guides avoid.

This book is a map, not the territory. It gives you the order, the milestones, and the warnings. But the walking is yours. Every chapter ends with an exercise. Do them. Do not skip them because they look easy. Do not skip them because you "already understand." Understanding without doing is an illusion.

Use this book like this: read a chapter, then write a small program using what you learned. When you finish a part, return to earlier programs and improve them. Learning to code is less like climbing a staircase and more like building a city — you revisit old neighborhoods with new tools.

"The best way to learn Python is to write Python."

There is no shortcut. There is no video you can watch that will make you a programmer. There is only the work. This book will make the work clearer.

Chapter One

What Python Is and Why It Matters

"Python is executable pseudocode. It reads like English, but it runs like a machine."

In This Chapter

  • What Python is and what it is used for
  • Where Python runs
  • Why it is worth learning
  • What makes it different from other languages

Python is a general-purpose programming language created by Guido van Rossum in 1991. It was designed to be readable, and it succeeded. Python code looks close to English. Where other languages use symbols and punctuation, Python uses indentation and words. This is why it is the most common first language taught in universities, and why it is used everywhere from web servers to scientific research to artificial intelligence.

You may not realize how much Python you already use. Instagram, Spotify, Dropbox, and Reddit run on Python. YouTube uses it for video processing. NASA uses it for scientific work. Google uses it in many internal tools. OpenAI's models are trained with Python. If you want to work in data, machine learning, automation, scripting, or backend development, Python is the language to know.

Why Python and Not Something Else

Every language has a personality. Python's personality is clarity. It was designed to make the simple things easy and the complex things possible. It removes the noise so you can focus on the problem.

Compare the same task in Python and in a lower-level language. In Python, you write print("hello"). In C, you write six lines and include a header. This difference matters for a beginner. Every line you do not have to write is a line you do not have to debug.

Python is also versatile. The same language that powers a data analysis script can power a web server, a game, a desktop application, or an artificial intelligence model. You do not have to switch languages to switch projects.

What Python Is Not

Python is not the fastest language in the world. For most tasks, it is fast enough. For the most demanding tasks — game engines, high-frequency trading, operating systems — other languages are better. But Python often connects to those languages: it calls C libraries for the heavy work while keeping the readable code in Python.

Python is also not a single program. There are many versions, many distributions, and many ways to install it. This can be confusing at first. We will sort it out in the next chapter.

How Python Is Used

FieldCommon tools
Web developmentDjango, Flask, FastAPI
Data analysispandas, NumPy, Jupyter
Machine learningPyTorch, TensorFlow, scikit-learn
Automation and scriptingStandard library, requests, Selenium

You do not need to choose a field yet. Learn the language first. The field can wait.

Key Takeaways

  • Python is a readable, general-purpose language.
  • It is used in web, data, AI, automation, and science.
  • It is fast enough for most tasks and easy to learn.
  • The same language works across many domains.

Chapter Two

Setting Up Your Workshop

"Give me six hours to chop down a tree and I will spend the first four sharpening the axe." — Abraham Lincoln

In This Chapter

  • Installing Python
  • Choosing an editor
  • Running your first program
  • Using the REPL for experiments

You do not need expensive software. You need two things: a Python installation and a code editor. Everything else is optional.

Installing Python

Go to python.org and download the latest stable version for your operating system. On Windows, during installation, check the box that says "Add Python to PATH." This is important. If you skip it, the python command will not work in your terminal.

On macOS, Python 3 is usually preinstalled, but it is often an older version. Install the latest from python.org anyway. On Linux, Python 3 is preinstalled on almost every distribution, but you may want a newer version.

To check your installation, open a terminal and type:

python --version

You should see something like Python 3.12.1. If you see Python 2, your system is using an old version. Try python3 instead. Python 2 is dead; use Python 3.

Choosing an Editor

Use Visual Studio Code. It is free, fast, and has excellent Python support. Install the official Python extension from Microsoft. This gives you syntax highlighting, autocompletion, and debugging.

Other fine editors include PyCharm (great for large projects), Sublime Text, and even a plain text editor. The editor matters less than you think. What matters is that you can write code and run it easily.

Your First Program

Create a folder called python-practice. Inside it, create a file called hello.py. Write this:

print("Hello, Python!")

In your terminal, navigate to the folder and run:

python hello.py

You should see the message printed. If you do, your workshop is ready.

The REPL

Python ships with a REPL — a Read-Eval-Print Loop. Type python with no file name and you enter an interactive session:

>>> 2 + 2
4
>>> "hello".upper()
'HELLO'
>>> [x * 2 for x in range(3)]
[0, 2, 4]

The REPL is perfect for quick experiments. Use it when you want to test a single line or check how something works. Exit with exit() or Ctrl+D.

Running Python Files

To run a file, use python filename.py. To pass arguments, add them after the file name. Your script can read them with sys.argv:

import sys
print(sys.argv)

Later, you will learn about virtual environments and other ways to organize projects. For now, keep it simple.

Key Takeaways

  • Install the latest Python 3 from python.org.
  • Add Python to PATH on Windows.
  • Use VS Code with the Python extension.
  • The REPL is your best tool for quick experiments.

Chapter Three

Variables and Values

"A variable is a name for a value. What you put inside is up to you."

In This Chapter

  • How to create variables in Python
  • Dynamic typing
  • Strings, numbers, and booleans
  • Naming conventions

A variable is a name for a value. You create one by assigning a value to a name. That is all. Every program you write will use variables to remember things: a user's name, a score, whether a checkbox is checked.

Creating Variables

In Python, you do not declare a variable. You just assign to it:

score = 0
name = "Ada"
is_active = True

There is no let, const, or var. You write the name, an equals sign, and a value. Python figures out the type from the value. This is called dynamic typing.

Dynamic Typing

Variables in Python do not have a fixed type. The name can be reassigned to a value of any type:

x = 5
x = "hello"
x = [1, 2, 3]

This is flexible, but it means Python will not catch type errors until the code runs. Use descriptive names and read your code carefully.

Primitive Types

Python has a small set of built-in types. The ones you will use constantly are:

TypeExampleUse
int42Whole numbers
float3.14Decimal numbers
str"hello"Text
boolTrue, FalseYes/no values
NoneTypeNoneAbsence of value

Notice that True and False are capitalized. Python is case-sensitive. true is not the same as True.

You can check the type of any value with type():

type("hello")   # <class 'str'>
type(42)        # <class 'int'>
type(3.14)      # <class 'float'>
type(True)      # <class 'bool'>
type(None)      # <class 'NoneType'>

Strings

Strings hold text. You can use single quotes or double quotes — they are equivalent. Triple quotes let you write multi-line strings:

first = "Ada"
last = 'Lovelace'
full = f"{first} {last}"   # "Ada Lovelace"

message = """
This is
a multi-line
string.
"""

The f before the string makes it an f-string. Inside the braces, you can put any expression:

name = "Ada"
age = 36
print(f"{name} is {age} years old.")

F-strings are the modern way to build strings. Use them.

Numbers

Python has two number types: int and float. Arithmetic works as you would expect:

10 + 3    # 13
10 / 3    # 3.3333333333333335
10 // 3   # 3   (floor division)
10 % 3    # 1   (remainder)
2 ** 8    # 256 (exponent)

Note that / always returns a float, even when the result is a whole number. Use // when you want an integer result.

Booleans

A boolean is either True or False. Booleans come from comparisons and logic, which we will cover in the next chapter.

Naming Variables

Python convention is snake_case: all lowercase, words separated by underscores. user_score is better than userScore. is_logged_in is better than flag. Use descriptive names. They will save you more time than any other habit.

Key Takeaways

  • Python uses dynamic typing — no declarations needed.
  • Use f-strings to build strings from variables.
  • True and False are capitalized.
  • Use snake_case for variable names.
  • Prefer descriptive names over short ones.

Chapter Four

Operators and Logic

"Programs are decisions written in arithmetic."

In This Chapter

  • Arithmetic operators
  • Comparison operators
  • Logical operators: and, or, not
  • Truthy and falsy values

Every decision your program makes comes down to a comparison. Is the score higher than ten? Is the user logged in? Is the password correct? Operators are how you ask those questions.

Arithmetic Operators

5 + 2    # 7
5 - 2    # 3
5 * 2    # 10
5 / 2    # 2.5
5 // 2   # 2   (floor division)
5 % 2    # 1   (remainder)
5 ** 2   # 25  (exponent)

The floor division // and remainder % operators are useful more often than beginners expect. Use % to test whether a number is even, or to wrap values into a range. Use // when you want a whole-number result.

Comparison Operators

OperatorMeaning
==Equal to
!=Not equal to
>Greater than
<Less than
>=Greater than or equal
<=Less than or equal

Python compares values intelligently. Strings compare alphabetically. Numbers compare numerically. Lists compare element by element.

"apple" < "banana"   # True
[1, 2, 3] < [1, 2, 4] # True
5 == 5.0              # True (int and float compare by value)

Logical Operators

Python uses words instead of symbols:

True and True    # True
True and False   # False
True or False    # True
not True         # False

Use these to combine conditions:

age = 20
has_license = True

if age >= 18 and has_license:
    print("You can drive.")

Truthy and Falsy

Every value in Python is either "truthy" or "falsy." The falsy values are:

  • False
  • None
  • 0, 0.0
  • "" (empty string)
  • [], (), {} (empty collections)

Everything else is truthy. This matters because if value: is shorthand for "if value is truthy":

name = ""
if name:
    print(f"Hello, {name}")
else:
    print("Name is empty.")

Chained Comparisons

Python lets you chain comparisons naturally:

age = 25
if 18 <= age < 65:
    print("Working age.")

This reads like math and is one of Python's small pleasures.

Key Takeaways

  • Use // for integer division and % for remainder.
  • Logical operators are and, or, not — words, not symbols.
  • Know the falsy values.
  • Chained comparisons read naturally.

Chapter Five

Control Flow

"A program without conditions is a straight line with no exits."

In This Chapter

  • if, elif, and else
  • The ternary expression
  • for loops
  • while loops
  • break and continue

Control flow is how your program decides what to do. Without it, code runs from top to bottom and stops. With it, code can branch, repeat, and skip.

if / elif / else

Python uses indentation to define blocks. There are no curly braces. The colon at the end of the condition starts the block:

score = 85

if score >= 90:
    print("A")
elif score >= 80:
    print("B")
elif score >= 70:
    print("C")
else:
    print("F")

Use four spaces for indentation. Not two, not a tab. Be consistent. Python will raise an error if you mix them.

The Ternary Expression

When you need a value based on a condition, use a conditional expression:

age = 20
label = "adult" if age >= 18 else "minor"

It reads: "adult if age is at least 18, otherwise minor." Use it for simple choices. For complex logic, use if.

for Loops

Python's for loop iterates over items, not counters. This is one of the features that makes Python feel natural:

fruits = ["apple", "banana", "cherry"]
for fruit in fruits:
    print(fruit)

Use range() when you need a sequence of numbers:

for i in range(5):
    print(i)  # 0 1 2 3 4

for i in range(1, 6):
    print(i)  # 1 2 3 4 5

for i in range(0, 10, 2):
    print(i)  # 0 2 4 6 8

while Loops

Use while when the number of repetitions is unknown:

count = 0
while count < 5:
    print(count)
    count += 1

Be careful. If the condition never becomes false, the loop runs forever and your program hangs. Press Ctrl+C to interrupt a runaway loop.

break and continue

Use break to exit a loop, and continue to skip to the next iteration:

for n in [1, 2, 3, 4, 5]:
    if n == 3:
        break
    print(n)  # 1 2

for n in [1, 2, 3, 4, 5]:
    if n % 2 == 0:
        continue
    print(n)  # 1 3 5

Looping with Indexes

When you need both the index and the value, use enumerate():

fruits = ["apple", "banana", "cherry"]
for i, fruit in enumerate(fruits):
    print(i, fruit)

When you need to iterate over two lists at once, use zip():

names = ["Ada", "Alan"]
ages = [36, 41]
for name, age in zip(names, ages):
    print(f"{name} is {age}")

Key Takeaways

  • Use if/elif/else for branching.
  • Python's for iterates over items, not counters.
  • Use range() for number sequences.
  • enumerate() and zip() handle common loop needs.
  • Indentation matters. Use four spaces.

Chapter Six

Functions

"A function is a named piece of behavior."

In This Chapter

  • Defining and calling functions
  • Parameters and return values
  • Default arguments and keyword arguments
  • Variable scope inside functions

A function is a block of code you can name and reuse. Every program larger than ten lines uses functions. They let you break a problem into pieces, name each piece, and test the pieces separately.

Defining a Function

def greet(name):
    return f"Hello, {name}!"

print(greet("Ada"))  # "Hello, Ada!"

The word name inside the parentheses is a parameter. The value you pass when calling the function ("Ada") is an argument. The return statement sends a value back to the caller.

If a function does not have a return, it returns None by default.

Default Arguments

def greet(name="friend"):
    return f"Hello, {name}!"

greet()        # "Hello, friend!"
greet("Ada")   # "Hello, Ada!"

Default arguments are evaluated once, when the function is defined. Do not use mutable defaults like lists or dictionaries unless you understand the consequences. Use None instead:

def add_item(item, items=None):
    if items is None:
        items = []
    items.append(item)
    return items

Keyword Arguments

When calling a function, you can name the arguments. This makes calls more readable and lets you skip optional parameters:

def create_user(name, age, admin=False):
    return {"name": name, "age": age, "admin": admin}

create_user(name="Ada", age=36)
create_user("Alan", 41, admin=True)

Arbitrary Arguments

Use *args for any number of positional arguments, and **kwargs for any number of keyword arguments:

def total(*numbers):
    return sum(numbers)

total(1, 2, 3, 4)  # 10

def describe(**info):
    for key, value in info.items():
        print(f"{key}: {value}")

describe(name="Ada", age=36)

Multiple Return Values

Python functions can return multiple values as a tuple:

def min_max(numbers):
    return min(numbers), max(numbers)

low, high = min_max([3, 1, 4, 1, 5, 9])
print(low, high)  # 1 9

Docstrings

Every function should have a short description called a docstring:

def greet(name):
    """Return a greeting for the given name."""
    return f"Hello, {name}!"

Docstrings are accessible with help(greet) or greet.__doc__. Write them for every function you intend to reuse.

Lambda Functions

A lambda is a small anonymous function. Use it when you need a quick function that you will not reuse:

double = lambda x: x * 2
double(5)  # 10

# Most common use: sorting with a key
words = ["banana", "apple", "cherry"]
words.sort(key=lambda w: len(w))
print(words)  # ['apple', 'banana', 'cherry']

If a lambda gets complicated, replace it with a regular function and a name. Readability always wins.

Key Takeaways

  • Define functions with def, return with return.
  • Use default arguments for optional parameters.
  • Use None as a default instead of mutable objects.
  • Use *args and **kwargs for flexible signatures.
  • Write docstrings. They are part of your code.

Chapter Seven

Lists and Tuples

"A list is a sequence. A tuple is a sequence that will not change."

In This Chapter

  • Creating and reading lists
  • Adding, removing, and slicing
  • When to use tuples
  • List methods you will use every day

A list is an ordered collection of values. Almost every real program works with lists: a list of users, a list of products, a list of messages. Lists are Python's most-used data structure. Learn them well.

Creating Lists

fruits = ["apple", "banana", "cherry"]
numbers = [1, 2, 3, 4, 5]
mixed = ["hello", 42, True, None]
empty = []

Reading and Writing

fruits[0]         # "apple"
fruits[-1]        # "cherry" (last item)
fruits[1]         # "banana"
len(fruits)       # 3

fruits[0] = "pear"  # ["pear", "banana", "cherry"]

Negative indexes count from the end. fruits[-1] is the last item, fruits[-2] is the one before it, and so on.

Slicing

Slicing gives you a sublist. The syntax is [start:end], where end is not included:

nums = [0, 1, 2, 3, 4, 5]
nums[1:4]     # [1, 2, 3]
nums[:3]      # [0, 1, 2]
nums[3:]      # [3, 4, 5]
nums[::2]     # [0, 2, 4] (every other item)
nums[::-1]    # [5, 4, 3, 2, 1] (reversed)

Slicing creates a new list. The original is unchanged.

Adding and Removing

nums = [1, 2, 3]

nums.append(4)      # [1, 2, 3, 4]       add to end
nums.insert(0, 0)   # [0, 1, 2, 3, 4]    insert at index
nums.remove(2)      # [0, 1, 3, 4]       remove by value
nums.pop()          # [0, 1, 3]          remove and return last
nums.pop(0)         # [1, 3]             remove and return at index
nums.clear()        # []                 remove everything

Common Methods

MethodWhat it does
append(x)Add x to the end
extend(iterable)Add every item from another iterable
insert(i, x)Insert x at index i
remove(x)Remove the first occurrence of x
pop([i])Remove and return item at index i
index(x)Return index of first occurrence of x
count(x)Count occurrences of x
sort()Sort in place
reverse()Reverse in place
copy()Return a shallow copy

Looping

for fruit in fruits:
    print(fruit)

for i, fruit in enumerate(fruits):
    print(i, fruit)

Checking Membership

"apple" in fruits     # True
"grape" in fruits     # False
3 not in [1, 2, 4]    # True

Tuples

A tuple is like a list, but it cannot be changed after creation. Tuples are written with parentheses:

point = (3, 5)
rgb = (255, 128, 0)
single = (42,)   # note the trailing comma for a one-element tuple

Use tuples when the data is fixed: coordinates, RGB values, or fixed pairs. Tuples are also faster than lists and can be used as dictionary keys (lists cannot).

Unpacking

You can unpack a list or tuple into individual variables:

point = (3, 5)
x, y = point
print(x, y)  # 3 5

first, *rest = [1, 2, 3, 4]
print(first)  # 1
print(rest)   # [2, 3, 4]

The *rest syntax collects any remaining items into a list. This is useful when you want the first or last item and the rest.

Key Takeaways

  • Lists are ordered, mutable sequences.
  • Tuples are ordered, immutable sequences.
  • Slicing with [start:end] creates a new list.
  • Use enumerate() when you need the index.
  • Use tuples for fixed data.

Chapter Eight

Dictionaries and Sets

"A dictionary is a collection of named values. A set is a collection of unique values."

In This Chapter

  • Creating and reading dictionaries
  • Adding, updating, and removing keys
  • Looping through dictionaries
  • Sets and when to use them

A dictionary is a collection of key-value pairs. Where lists are ordered by index, dictionaries are ordered by key. If you want to describe a person, you do not use a list of values; you use a dictionary with named properties.

Creating Dictionaries

user = {
    "name": "Ada",
    "age": 36,
    "is_admin": True,
}

empty = {}
also_empty = dict()

Reading and Writing

user["name"]              # "Ada"
user["age"] = 37          # update
user["email"] = "ada@example.com"  # add new key

user.get("name")          # "Ada"
user.get("phone")         # None (no error)
user.get("phone", "n/a")  # "n/a" (default)

Use .get() when the key might not exist. Accessing a missing key with [] raises a KeyError.

Checking for Keys

"name" in user    # True
"phone" in user   # False

Removing Keys

del user["age"]
user.pop("email", None)   # remove safely, return None if missing
user.clear()              # remove everything

Looping

for key in user:
    print(key)

for value in user.values():
    print(value)

for key, value in user.items():
    print(key, value)

Use .items() when you need both the key and the value. It is the most common pattern.

Nested Data

Dictionaries can contain lists, other dictionaries, or anything else. Real data often looks like a list of dictionaries:

users = [
    {"name": "Ada", "age": 36},
    {"name": "Alan", "age": 41},
    {"name": "Grace", "age": 45},
]

for user in users:
    print(user["name"])

names = [user["name"] for user in users]
print(names)  # ["Ada", "Alan", "Grace"]

Sets

A set is an unordered collection of unique values. Sets are written with curly braces, but without key-value pairs:

colors = {"red", "green", "blue"}
numbers = {1, 2, 3, 3, 3}   # {1, 2, 3} — duplicates removed
empty = set()               # note: {} creates an empty dict, not a set

Use sets to remove duplicates from a list:

nums = [1, 2, 2, 3, 3, 3]
unique = list(set(nums))    # [1, 2, 3]

Use sets for fast membership tests:

allowed = {"admin", "editor"}
if "admin" in allowed:
    print("Welcome")

Set Operations

a = {1, 2, 3}
b = {3, 4, 5}

a | b    # {1, 2, 3, 4, 5}  union
a & b    # {3}              intersection
a - b    # {1, 2}           difference
a ^ b    # {1, 2, 4, 5}     symmetric difference

Set operations are useful for comparing lists: which items do two lists share? Which items are in one but not the other?

Key Takeaways

  • Dictionaries store key-value pairs.
  • Use .get() instead of [] when the key might be missing.
  • Use .items() to loop with both key and value.
  • Sets store unique values and are fast for membership tests.
  • Real data often looks like a list of dictionaries.

Chapter Ten

Scope and Namespaces

"Where a name lives determines what it can see."

In This Chapter

  • Local, enclosing, global, and built-in scopes
  • The global and nonlocal keywords
  • Why scoping matters in functions

These ideas separate programmers who guess from programmers who know. Read this chapter twice. The rules are simple, but the consequences are deep.

The Four Scopes

Python looks up names in four places, in order:

  1. Local — names inside the current function
  2. Enclosing — names in an outer function
  3. Global — names at the top level of the module
  4. Built-in — names Python provides, like print and len

This is often called the LEGB rule. When you use a name, Python searches Local, then Enclosing, then Global, then Built-in.

x = "global"

def outer():
    x = "enclosing"
    def inner():
        x = "local"
        print(x)   # "local"
    inner()

outer()

Modifying Globals

If you assign to a name inside a function, Python treats it as local unless you say otherwise. To modify a global, use global:

count = 0

def increment():
    global count
    count += 1

increment()
print(count)  # 1

Use global sparingly. Global state makes code hard to reason about. Prefer passing values as arguments and returning results.

Enclosing Scope with nonlocal

To modify a variable in an enclosing function, use nonlocal:

def counter():
    count = 0
    def increment():
        nonlocal count
        count += 1
        return count
    return increment

next_count = counter()
print(next_count())  # 1
print(next_count())  # 2
print(next_count())  # 3

This pattern is called a closure, and it is one of the most useful tools in Python.

Why This Matters

When a bug appears, "why is this variable not what I think it is?" is often a scope question. Knowing the rules saves hours. The fix is usually to rename a variable, pass a parameter, or restructure the code so the scope is obvious.

Key Takeaways

  • Python uses the LEGB rule for name lookup.
  • Assignments inside a function create local variables by default.
  • Use global sparingly.
  • Use nonlocal to modify enclosing variables.
  • Closures are built on enclosing scope.

Chapter Eleven

References and Mutability

"Assignment binds a name to an object. It does not copy the object."

In This Chapter

  • The difference between names and objects
  • Mutable vs immutable types
  • How references cause surprising bugs
  • How to copy correctly

This chapter explains the most common source of beginner bugs in Python. Once you understand references and mutability, you will stop being surprised when your lists change unexpectedly.

Names and Objects

In Python, a variable is a name bound to an object. When you write x = [1, 2, 3], you create a list object and bind the name x to it. The name is not the object. This distinction matters.

a = [1, 2, 3]
b = a
b.append(4)

print(a)   # [1, 2, 3, 4]
print(b)   # [1, 2, 3, 4]

Both a and b point to the same list. When you change it through one name, you see the change through the other. This is not a bug. It is how Python works.

Mutable vs Immutable

ImmutableMutable
int, float, boollist
strdict
tupleset
frozensetcustom objects (usually)

Immutable objects cannot be changed. When you "change" a string, you actually create a new string and rebind the name. Mutable objects can be changed in place, and every name that points to them sees the change.

Copying Lists

To create an independent copy of a list, use slicing or the .copy() method:

a = [1, 2, 3]
b = a.copy()      # or b = a[:]
b.append(4)

print(a)   # [1, 2, 3]
print(b)   # [1, 2, 3, 4]

These are shallow copies. If the list contains other mutable objects, those objects are still shared. For nested structures, use copy.deepcopy() from the copy module.

Function Arguments

When you pass a list to a function, the function receives a reference to the same list. If the function modifies it, the caller sees the change:

def add_item(items, item):
    items.append(item)

my_list = [1, 2, 3]
add_item(my_list, 4)
print(my_list)  # [1, 2, 3, 4]

This is sometimes useful and sometimes surprising. If you do not want the function to modify the caller's list, pass a copy or return a new list.

The "Mutable Default Argument" Bug

Default arguments are evaluated once, when the function is defined. This leads to a classic bug:

def add_item(item, items=[]):
    items.append(item)
    return items

add_item(1)   # [1]
add_item(2)   # [1, 2] — surprising!
add_item(3)   # [1, 2, 3]

The same list is reused across calls. Always use None as a default for mutable arguments:

def add_item(item, items=None):
    if items is None:
        items = []
    items.append(item)
    return items

Memorize this pattern. It will save you from a bug that confuses even experienced developers.

Key Takeaways

  • Assignment binds a name to an object; it does not copy.
  • Mutable objects can be changed in place.
  • Use .copy() or slicing for a shallow copy.
  • Never use mutable default arguments — use None.

Chapter Twelve

Truthiness and the Zen of Python

"Beautiful is better than ugly. Explicit is better than implicit." — The Zen of Python

In This Chapter

  • Truthy and falsy values in detail
  • The is operator vs ==
  • The Zen of Python
  • Writing Pythonic code

Python has a philosophy, and it is written into the language itself. You can read it by typing import this in the REPL. This chapter is about that philosophy and the small details that flow from it.

Truthiness Recap

Falsy values: False, None, 0, 0.0, "", [], (), {}, set(). Everything else is truthy.

This leads to Pythonic patterns:

name = ""
if name:
    print(f"Hello, {name}")
else:
    print("No name given.")

items = []
if not items:
    print("The list is empty.")

Do not write if len(items) == 0:. Write if not items:. Do not write if name != "":. Write if name:. These are shorter and clearer once you are used to them.

is vs ==

Use == to compare values. Use is to compare identity — whether two names point to the same object.

a = [1, 2, 3]
b = [1, 2, 3]
c = a

a == b    # True (same values)
a is b    # False (different objects)
a is c    # True (same object)

Use is mainly to compare with None:

if value is None:
    print("No value.")

Never write if value == None. It works, but is None is the correct idiom and is faster.

The Zen of Python

Type import this in the REPL and you will see a list of principles. A few of the most important:

  • Beautiful is better than ugly. Write code you would be happy to read.
  • Explicit is better than implicit. Do not rely on hidden magic.
  • Simple is better than complex. When two solutions work, choose the simpler one.
  • Readability counts. Always.
  • Errors should never pass silently. Handle them, do not hide them.
  • If the implementation is hard to explain, it is a bad idea. Clarity is a design principle.

These are not just slogans. They guide the design of the language and of good code written in it. Learning to write Pythonic code is part of learning Python.

Pythonic Patterns

# Instead of:
if x == True:
    ...

# Write:
if x:
    ...

# Instead of:
for i in range(len(items)):
    print(items[i])

# Write:
for item in items:
    print(item)

# Instead of:
if x != None:
    ...

# Write:
if x is not None:
    ...

# Instead of:
result = []
for x in nums:
    result.append(x * 2)

# Write:
result = [x * 2 for x in nums]

These patterns are not rules. They are conventions that experienced Python programmers follow because they make code shorter, clearer, and easier to maintain.

Key Takeaways

  • Use truthiness instead of comparing to True or False.
  • Use is for identity, == for value.
  • Use is None, not == None.
  • The Zen of Python is real. Read it once a month.

Chapter Thirteen

Comprehensions

"A comprehension is a loop with a purpose."

In This Chapter

  • List comprehensions
  • Filtering with conditions
  • Dict and set comprehensions
  • When not to use them

A comprehension is a compact way to build a list, dictionary, or set from another iterable. It replaces the common pattern of creating an empty collection, looping, and appending. Comprehensions are one of the features that make Python feel pleasant.

List Comprehensions

nums = [1, 2, 3, 4, 5]

doubled = [n * 2 for n in nums]
# [2, 4, 6, 8, 10]

evens = [n for n in nums if n % 2 == 0]
# [2, 4]

squares = [n ** 2 for n in nums]
# [1, 4, 9, 16, 25]

The syntax is [expression for item in iterable if condition]. The condition is optional.

Nested Comprehensions

matrix = [[1, 2], [3, 4], [5, 6]]

flattened = [n for row in matrix for n in row]
# [1, 2, 3, 4, 5, 6]

Read nested comprehensions left to right, as if they were nested loops. If the result is hard to read, use a regular loop instead.

Dictionary Comprehensions

names = ["Ada", "Alan", "Grace"]

lengths = {name: len(name) for name in names}
# {"Ada": 3, "Alan": 4, "Grace": 5}

# Inverting a dictionary
original = {"a": 1, "b": 2, "c": 3}
inverted = {v: k for k, v in original.items()}
# {1: "a", 2: "b", 3: "c"}

Set Comprehensions

words = ["apple", "banana", "apple", "cherry"]

unique_lengths = {len(w) for w in words}
# {5, 6}

Set comprehensions remove duplicates automatically.

Conditional Expressions Inside Comprehensions

nums = [1, 2, 3, 4, 5]

labels = ["even" if n % 2 == 0 else "odd" for n in nums]
# ["odd", "even", "odd", "even", "odd"]

This is different from a filter. A filter removes items. A conditional expression transforms each item.

When Not to Use Comprehensions

Comprehensions are great for simple transformations. They are terrible for complex logic. If a comprehension does not fit on one or two lines, or if you have to squint to read it, use a regular loop. Readability always wins.

# Hard to read:
result = [x if x % 2 == 0 else y * 2 for x, y in pairs if x > 0 and y < 10]

# Better:
result = []
for x, y in pairs:
    if x > 0 and y < 10:
        result.append(x if x % 2 == 0 else y * 2)

Key Takeaways

  • Comprehensions replace loops that build collections.
  • Use them for simple transformations and filters.
  • Dict and set comprehensions use the same idea.
  • Use a regular loop when the logic is complex.

Chapter Fourteen

Files, JSON, and Paths

"Programs without files forget everything when they close."

In This Chapter

  • Reading and writing files
  • The with statement
  • Working with JSON
  • Building paths with pathlib

Files are how programs remember things. Any program that saves data, loads configuration, or reads user input from disk needs file handling. Python makes this easy.

Reading Files

The modern way to open a file is with the with statement. It closes the file automatically, even if something goes wrong:

with open("data.txt", "r", encoding="utf-8") as f:
    content = f.read()

print(content)

The mode "r" means read. Other modes: "w" for write (overwrites), "a" for append, and "rb" or "wb" for binary.

Reading Line by Line

with open("data.txt", "r", encoding="utf-8") as f:
    for line in f:
        print(line.rstrip())

Use .rstrip() to remove the trailing newline. Each line from the file includes the \n character.

Writing Files

with open("output.txt", "w", encoding="utf-8") as f:
    f.write("Hello, file!\n")
    f.write("Second line.\n")

Opening a file with "w" erases any existing content. Use "a" to add to the end instead.

JSON

JSON is the standard format for structured data. Python's json module converts between Python objects and JSON text:

import json

data = {
    "name": "Ada",
    "age": 36,
    "skills": ["math", "writing"],
}

# Write to file
with open("user.json", "w", encoding="utf-8") as f:
    json.dump(data, f, indent=2)

# Read from file
with open("user.json", "r", encoding="utf-8") as f:
    loaded = json.load(f)

print(loaded["name"])   # "Ada"
print(loaded["skills"]) # ["math", "writing"]

Use json.dumps and json.loads to convert to and from strings instead of files.

Pathlib

The pathlib module is the modern way to work with paths. It replaces the older os.path functions and is much nicer:

from pathlib import Path

# Current directory
here = Path.cwd()

# Build a path
file = Path("data") / "users.json"

# Check existence
if file.exists():
    print("Found!")

# Create a directory
Path("output").mkdir(exist_ok=True)

# List files
for path in Path(".").glob("*.py"):
    print(path)

Use Path for everything. It handles platform differences, joining paths, and reading directories cleanly.

Key Takeaways

  • Use with open(...) for file handling.
  • Modes: "r" read, "w" write, "a" append.
  • Use the json module for structured data.
  • Use pathlib.Path for paths.

Chapter Fifteen

Errors and Exceptions

"Errors are not failures. They are information."

In This Chapter

  • Reading error messages
  • try, except, finally
  • Raising exceptions
  • Custom exceptions

Every program has errors. The question is what happens when they occur. Ignoring errors leads to silent bugs. Handling them well is what separates beginner code from professional code.

Reading Errors

When Python hits a problem, it raises an exception. The traceback shows where the error happened and what type it was:

Traceback (most recent call last):
  File "app.py", line 3, in <module>
    print(10 / 0)
ZeroDivisionError: division by zero

Read the traceback from the bottom up. The last line is the type of error and a short description. Above it, the chain of calls leading to it.

Common Exceptions

ExceptionWhen it occurs
NameErrorUsing a name that is not defined
TypeErrorWrong type for an operation
ValueErrorRight type, wrong value
KeyErrorMissing dictionary key
IndexErrorList index out of range
ZeroDivisionErrorDividing by zero
FileNotFoundErrorTrying to open a missing file

try / except

Wrap risky code in a try block and handle errors in an except block:

try:
    number = int(input("Enter a number: "))
    print(10 / number)
except ValueError:
    print("That was not a number.")
except ZeroDivisionError:
    print("Cannot divide by zero.")

Catch specific exceptions. Do not write a bare except: that hides every error — that makes debugging much harder.

finally

The finally block runs whether an exception occurred or not. Use it for cleanup:

try:
    f = open("data.txt")
    content = f.read()
finally:
    f.close()

In modern Python, you rarely need finally for files because with handles cleanup. But finally is still useful for other resources like database connections.

Raising Exceptions

When your own code detects a problem, raise an exception with raise:

def withdraw(balance, amount):
    if amount <= 0:
        raise ValueError("Amount must be positive.")
    if amount > balance:
        raise ValueError("Insufficient funds.")
    return balance - amount

Raising early, with a clear message, saves hours of debugging later.

Custom Exceptions

For larger programs, define your own exception types by subclassing Exception:

class InsufficientFundsError(Exception):
    pass

def withdraw(balance, amount):
    if amount > balance:
        raise InsufficientFundsError("Not enough money.")
    return balance - amount

Custom exceptions let you catch errors by category and make your code self-documenting.

Key Takeaways

  • Read tracebacks from the bottom up.
  • Catch specific exceptions, not every exception.
  • Use raise to signal problems in your code.
  • Custom exceptions make larger programs cleaner.

Chapter Sixteen

Classes and Objects

"A class is a blueprint. An object is a thing built from it."

In This Chapter

  • Defining classes
  • The __init__ method
  • Instance methods and attributes
  • Inheritance and dunder methods

A class bundles data and behavior together. Where a dictionary stores values, a class stores values and the functions that operate on them. Classes are how larger Python programs organize state.

Defining a Class

class Dog:
    def __init__(self, name, age):
        self.name = name
        self.age = age

    def bark(self):
        return f"{self.name} says woof!"

d = Dog("Rex", 3)
print(d.name)      # "Rex"
print(d.bark())    # "Rex says woof!"

The __init__ method runs when you create an object. It sets up the initial state. The first parameter is always self, a reference to the object being created.

Attributes and Methods

Attributes are values stored on the object. Methods are functions defined inside the class. Access both with dot notation:

d.name          # attribute
d.bark()        # method
d.age = 4       # update attribute
d.color = "brown"  # add new attribute (allowed, but avoid)

The __str__ Method

Define __str__ to control what print() shows:

class Dog:
    def __init__(self, name, age):
        self.name = name
        self.age = age

    def __str__(self):
        return f"Dog(name={self.name}, age={self.age})"

print(Dog("Rex", 3))  # Dog(name=Rex, age=3)

The methods with double underscores are called dunder methods (double underscore). They hook into Python's built-in behavior: printing, comparing, iterating, and more.

Inheritance

A class can inherit from another, reusing its behavior and adding new behavior:

class Animal:
    def __init__(self, name):
        self.name = name

    def speak(self):
        return "Some sound"

class Dog(Animal):
    def speak(self):
        return f"{self.name} says woof!"

class Cat(Animal):
    def speak(self):
        return f"{self.name} says meow!"

animals = [Dog("Rex"), Cat("Whiskers")]
for a in animals:
    print(a.speak())

The subclasses override speak. When you loop through a list of animals and call speak(), Python picks the right version for each object. This is called polymorphism.

Useful Dunder Methods

MethodPurpose
__init__Initialize the object
__str__String representation for printing
__repr__Developer-friendly representation
__eq__Equality with ==
__len__Length with len()
__iter__Make the object iterable

When to Use Classes

Use a class when you have data and behavior that belong together and you will create many instances. Use a dictionary when the data is simple and short-lived. Do not use classes just because you can; use them when they make the code clearer.

Key Takeaways

  • Classes bundle data and behavior.
  • __init__ runs on creation.
  • self refers to the current object.
  • Dunder methods hook into Python's built-in behavior.
  • Use classes when you have data and behavior that belong together.

Chapter Seventeen

Modules and Packages

"A module is a file. A package is a folder of files."

In This Chapter

  • Importing modules
  • Writing your own modules
  • The if __name__ == "__main__" pattern
  • Packages and __init__.py

A module is a Python file. A package is a folder of modules. As your programs grow, splitting them into modules keeps everything organized and reusable. The same skills let you use the standard library and third-party packages.

Importing

import math
math.sqrt(16)   # 4.0

from math import sqrt
sqrt(16)        # 4.0

from math import sqrt as square_root
square_root(16) # 4.0

Use import module when you want to be explicit about where names come from. Use from module import name when you use the name often and the source is obvious. Avoid from module import *; it pollutes your namespace with names you cannot see.

Writing a Module

Any .py file can be imported. Create math_tools.py:

def add(a, b):
    return a + b

def multiply(a, b):
    return a * b

PI = 3.14159

Then in another file:

import math_tools

print(math_tools.add(2, 3))       # 5
print(math_tools.PI)              # 3.14159

The module is only executed once, the first time it is imported. Subsequent imports reuse the same module.

The __main__ Guard

When a module runs as a script, Python sets __name__ to "__main__". When it is imported, __name__ is the module's name. This lets a file be both a script and an importable module:

def main():
    print("Running as a script.")

if __name__ == "__main__":
    main()

Use this pattern in every file that has a main entry point. It prevents code from running when the file is imported.

Packages

A package is a folder containing modules and an __init__.py file. The __init__.py can be empty, or it can run setup code when the package is imported:

myproject/
├── __init__.py
├── utils.py
└── models.py

Then:

from myproject import utils
from myproject.models import User

Relative Imports

Inside a package, you can import sibling modules with a dot:

from . import utils
from .models import User

Relative imports only work inside packages. They are not allowed in scripts that are run directly.

Key Takeaways

  • Every .py file is a module.
  • Use import and from ... import ... deliberately.
  • Guard script code with if __name__ == "__main__":.
  • A package is a folder of modules with an __init__.py.

Chapter Nineteen

Virtual Environments and pip

"Every project deserves its own room."

In This Chapter

  • Why virtual environments exist
  • Creating and activating one
  • Installing packages with pip
  • Freezing dependencies

Every serious Python project needs a virtual environment. If you install packages globally, you will eventually break your system Python or create conflicts between projects. Virtual environments solve this by giving each project its own isolated set of packages.

Creating a Virtual Environment

From your project folder:

python -m venv .venv

This creates a folder called .venv with its own Python interpreter and its own site-packages directory.

Activating It

On macOS or Linux:

source .venv/bin/activate

On Windows (PowerShell):

.venv\Scripts\Activate.ps1

On Windows (cmd):

.venv\Scripts\activate.bat

Your prompt will change to show the environment name. Now, anything you install or run will use this environment.

Installing Packages

pip install requests
pip install pandas
pip install pytest

To see what is installed:

pip list

Freezing Dependencies

When you want to share your project, save the exact versions you are using:

pip freeze > requirements.txt

Someone else can then install everything:

pip install -r requirements.txt

Deactivating

When you are done:

deactivate

This returns you to the system Python. Never install project packages outside a virtual environment. Make activating the environment the first thing you do when you sit down to work on a project.

Key Takeaways

  • Use one virtual environment per project.
  • Create with python -m venv .venv.
  • Activate before installing anything.
  • Freeze dependencies with pip freeze.

Chapter Twenty

Iterators, Generators, and Decorators

"Some of Python's most powerful ideas hide behind small keywords."

In This Chapter

  • How iteration works
  • Generators with yield
  • Decorators
  • Why these matter in real code

This chapter is a step up in abstraction. If you understand iteration, generators, and decorators, you will read other people's Python code with much more confidence — and you will find that these tools solve problems that would otherwise be awkward.

Iterators

An iterable is anything you can loop over. An iterator is the object that produces the next value. Under the hood, Python uses __iter__ and __next__ to make this work. You rarely write these yourself, but knowing they exist explains a lot.

nums = [1, 2, 3]
it = iter(nums)
print(next(it))  # 1
print(next(it))  # 2
print(next(it))  # 3
# next(it) now raises StopIteration

Generators

A generator is a function that produces values one at a time using yield. It does not compute all values at once; it produces them lazily, on demand:

def count_up_to(n):
    i = 1
    while i <= n:
        yield i
        i += 1

for n in count_up_to(5):
    print(n)  # 1 2 3 4 5

Generators are memory-efficient. They can represent infinite sequences because they only produce values as needed. Use them for large data, streams, or pipelines.

def read_lines(path):
    with open(path) as f:
        for line in f:
            yield line.rstrip()

for line in read_lines("big.txt"):
    print(line)

This reads a file line by line without loading the whole file into memory.

Generator Expressions

Like list comprehensions, but with parentheses instead of square brackets:

squares = (n ** 2 for n in range(10))
sum(squares)  # 285

# Or in one line:
total = sum(n ** 2 for n in range(10))

Use generator expressions when you only need to consume the values once and do not want to store them in memory.

Decorators

A decorator is a function that wraps another function to add behavior. You apply it with the @ symbol:

def log_calls(func):
    def wrapper(*args, **kwargs):
        print(f"Calling {func.__name__} with {args}")
        result = func(*args, **kwargs)
        print(f"{func.__name__} returned {result}")
        return result
    return wrapper

@log_calls
def add(a, b):
    return a + b

add(2, 3)
# Calling add with (2, 3)
# add returned 5

Decorators are used everywhere in real code: caching, authentication, timing, retries, and more. Once you understand them, you will see them in every library you use.

A Practical Example

import time
from functools import wraps

def timed(func):
    @wraps(func)
    def wrapper(*args, **kwargs):
        start = time.time()
        result = func(*args, **kwargs)
        elapsed = time.time() - start
        print(f"{func.__name__} took {elapsed:.4f}s")
        return result
    return wrapper

@timed
def slow_function():
    time.sleep(1)

slow_function()  # prints: slow_function took 1.0000s

The @wraps decorator preserves the original function's name and docstring, which is important for debugging and documentation.

Key Takeaways

  • Generators produce values lazily with yield.
  • Use generators for large data or streaming.
  • Decorators wrap functions to add behavior.
  • Use @wraps on your wrappers.

Chapter Twenty-One

Testing Your Code

"If it is not tested, it is broken."

In This Chapter

  • Why testing matters
  • Writing tests with pytest
  • Test-driven development
  • What to test and what not to

Tests are code that checks other code. They catch bugs before your users do, they let you refactor with confidence, and they document what your code is supposed to do. Every professional Python programmer writes tests.

Your First Test

Install pytest inside your virtual environment:

pip install pytest

Suppose you have a function in calc.py:

def add(a, b):
    return a + b

Create a file called test_calc.py:

from calc import add

def test_add_positive_numbers():
    assert add(2, 3) == 5

def test_add_negative_numbers():
    assert add(-1, -1) == -2

def test_add_zero():
    assert add(0, 5) == 5

Run:

pytest

Pytest finds files starting with test_, runs functions starting with test_, and reports pass or fail.

Testing Exceptions

import pytest

def test_division_by_zero():
    with pytest.raises(ZeroDivisionError):
        1 / 0

The pytest.raises context manager fails the test if the expected exception is not raised.

Test-Driven Development

TDD is a workflow: write the test first, watch it fail, then write the code to make it pass. This sounds backward, but it forces you to think about the interface before the implementation and it guarantees every line you write is tested.

  1. Write a failing test.
  2. Write the simplest code that passes.
  3. Refactor.
  4. Repeat.

What to Test

Test the behavior, not the implementation. Test the edges: empty inputs, zero, negative numbers, very large values. Test that errors are raised when they should be. Do not test private functions or trivial getters and setters.

What Not to Do

Do not chase 100% coverage. Do not write tests that only pass because they check the same wrong assumption as the code. Do not write tests that depend on the order they run. A good test fails when the code is wrong and passes when it is right — nothing more, nothing less.

Key Takeaways

  • Tests catch bugs before users do.
  • Use pytest — it is simple and powerful.
  • Test behavior, not implementation.
  • Test the edges: empty, zero, negative, huge.

Chapter Twenty-Three

How to Practice

"Knowledge comes from reading. Skill comes from doing."

This chapter matters more than any resource list. Learning to code is not about collecting information. It is about building skill, and skill comes from deliberate practice.

  1. Code every day. Even 30 minutes beats 5 hours once a week. Consistency builds muscle memory.
  2. Build projects, not tutorials. After each tutorial, close it and rebuild the same thing from memory. This is where the real learning happens.
  3. Struggle first. Try to solve a problem for 20–30 minutes before looking up the answer. The struggle is the learning.
  4. Read error messages. They tell you the file, the line, and often the exact problem. Most beginners ignore them and lose hours.
  5. Use the REPL. Test a single line or check how something behaves before writing a whole file.
  6. Teach someone else. Explaining decorators or generators out loud exposes the gaps in your understanding.
  7. Revisit old projects. Every few weeks, return to something you built and improve it. You will be surprised how much you have learned.

Key Takeaways

  • Consistency beats intensity.
  • Build, do not just watch.
  • Struggle before looking up the answer.
  • Teach to test your understanding.
Chapter Twenty-Four

Common Pitfalls

"The mistakes are predictable. Knowing them in advance saves months."

Every beginner makes some of these mistakes. The point is not to avoid them entirely but to recognize them quickly and correct course.

  • Tutorial hell. Watching videos endlessly without building anything yourself. Break the cycle by building after every tutorial.
  • Skipping fundamentals. Jumping to pandas or Django before understanding Python. Frameworks are easier when the language is solid.
  • Mutable default arguments. The bug that catches everyone once. Use None as the default.
  • Ignoring virtual environments. Installing packages globally will break something. Always use a venv.
  • Fear of breaking things. You cannot break your computer by writing Python. Experiment freely.
  • Comparing yourself to others. Everyone learns at a different pace. The only useful comparison is to yourself a month ago.
  • Chasing every new library. You do not need the newest tool. Learn the language first.
  • Giving up too early. The first three months are the hardest. Push through. It gets easier.

Key Takeaways

  • Tutorial hell is real. Build to escape it.
  • Fundamentals first. Libraries later.
  • Virtual environments are not optional.
  • The first three months are the hardest.
