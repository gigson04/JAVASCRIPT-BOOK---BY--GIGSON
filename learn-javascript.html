Front Matter

Preface: How to Use This Book

JavaScript is not learned by reading. It is learned by writing. You can read every page of this book and still not know JavaScript if you never open a code editor, make mistakes, and fix them. That is the uncomfortable truth that most beginner guides avoid.

This book is a map, not the territory. It gives you the order, the milestones, and the warnings. But the walking is yours. Every chapter ends with an exercise or a project. Do them. Do not skip them because they look easy. Do not skip them because you "already understand." Understanding without doing is an illusion.

Use this book like this: read a chapter, then build something small with what you learned. When you finish a part, return to the projects you built earlier and improve them. Learning to code is less like climbing a staircase and more like building a city — you revisit old neighborhoods with new tools.

"The best way to learn JavaScript is to write JavaScript."

There is no shortcut. There is no video you can watch that will make you a developer. There is only the work. This book will make the work clearer.

Chapter One

What JavaScript Is and Why It Matters

"Any application that can be written in JavaScript will eventually be written in JavaScript." — Jeff Atwood

In This Chapter

  • What JavaScript is and what it does
  • Where JavaScript runs
  • Why it is worth learning
  • How it relates to HTML and CSS

Every website you have ever used is built from three languages. HTML provides structure. CSS provides style. JavaScript provides behavior. If a page can move, respond, calculate, load new data, or react to you in any way, JavaScript is doing the work.

When you click a button and a menu opens, that is JavaScript. When you type into a search bar and suggestions appear, that is JavaScript. When you scroll down and more posts load automatically, that is JavaScript. When you submit a form and see an error before the page reloads, that is JavaScript.

JavaScript began in 1995 as a small scripting language for a single browser. Today it runs almost everywhere. It runs in every major browser, on servers through Node.js, on mobile devices through React Native, on desktop through Electron, and even on microcontrollers. It is the only language that runs natively in the browser, which makes it the one language every web developer must know.

What JavaScript Is Not

JavaScript is not Java. The two languages share a name and some syntax, but they are unrelated. The name was a marketing decision made in the 1990s. Ignore the confusion; it has no bearing on your learning.

JavaScript is also not a single company's product. It is standardized by a group called ECMA, and the official name of the language is ECMAScript. When you hear "ES6" or "ES2020," those are versions of the standard. Modern JavaScript means the features added in ES6 (2015) and everything after.

Why Learn JavaScript

You should learn JavaScript because it is unavoidable. Every front-end framework — React, Vue, Svelte, Angular — is built on top of it. Every browser API assumes you know it. Every job listing for a web developer expects it. You cannot skip JavaScript and become a web developer. You can only delay the inevitable.

But the better reason is this: JavaScript is the fastest way to make something appear on screen that responds to a human being. You can write ten lines and see a button change color. You can write thirty and build a working calculator. That immediate feedback loop is what makes programming addictive, and JavaScript gives it to you faster than almost any other language.

How It Relates to HTML and CSS

Think of a webpage as a house. HTML is the walls and rooms. CSS is the paint and furniture. JavaScript is the electricity — the lights that turn on, the doors that open, the thermostat that responds to temperature.

You cannot meaningfully learn JavaScript without knowing a little HTML and CSS. You do not need mastery. You need enough to build a page with a heading, a paragraph, a button, and a class name you can target. If you can do that, you are ready.

Key Takeaways

  • JavaScript adds behavior to web pages.
  • It runs in browsers, servers, mobile apps, and more.
  • It is not related to Java.
  • You need basic HTML and CSS before starting.

Exercise 1.1

  2. Right-click the page and choose "Inspect."
  3. Find the tab labeled "Console."
  4. Type document.title and press Enter.
  5. Notice that you are already running JavaScript on a real page.
Chapter Two

Setting Up Your Workshop

"Give me six hours to chop down a tree and I will spend the first four sharpening the axe." — Abraham Lincoln

In This Chapter

  • The three tools you actually need
  • How to run JavaScript
  • How to debug with the console
  • How to stay organized from day one

You do not need expensive software. You do not need a special computer. You need three things: a browser, a code editor, and a folder on your computer where you keep your work.

The Browser

Use Chrome, Firefox, Edge, or Safari. All of them run JavaScript. All of them include developer tools. To open the tools, press F12 on Windows or Cmd + Option + I on Mac. The Console tab is where you will spend most of your debugging time. It shows errors, prints values, and lets you run code directly.

The Code Editor

Use Visual Studio Code. It is free, fast, and the industry standard. Alternatives like Sublime Text and Atom work fine, but VS Code has the best JavaScript support out of the box.

Install the following extensions to make your life easier:

  • Prettier — formats your code automatically
  • ESLint — catches common mistakes
  • Live Server — reloads your page when you save

Your First File

Create a folder called javascript-practice. Inside it, create a file called index.html. Paste this in:

<!DOCTYPE html>
<html>
<head>
  <title>Practice</title>
</head>
<body>
  <h1>Hello, JavaScript</h1>
  <script src="app.js"></script>
</body>
</html>

Now create app.js in the same folder:

console.log("JavaScript is running.");

Open index.html in your browser. Press F12 and look at the Console tab. You should see your message. If you do, your workshop is ready.

How to Run JavaScript Without a File

For quick experiments, you do not need a file at all. Open the browser console and type directly into it. This is perfect for testing a single line or checking what a function does.

2 + 2
"hello".toUpperCase()
[1, 2, 3].map(n => n * 2)

Debugging Basics

When something does not work, the console is your first stop. Errors appear in red. Read them carefully. They tell you the file, the line, and often the exact problem. The most common beginner errors are typos, missing brackets, and misspelled variable names.

Use console.log() generously. Print values before and after the code you suspect. This is called "printf debugging," and professionals still use it every day.

Key Takeaways

  • You only need a browser, VS Code, and a folder.
  • The Console tab is your best tool.
  • You can run JavaScript directly in the console.
  • Read error messages — they usually tell you what is wrong.

Chapter Three

Variables and Values

"A variable is a named box. What you put inside is up to you."

In This Chapter

  • How to declare variables with let and const
  • The primitive types: string, number, boolean, null, undefined
  • How to name variables well
  • Why var exists but should be avoided

A variable is a name for a value. You create one, give it a value, and refer to it later. That is all. Every program you write will use variables to remember things: a user's name, a score, a list of items, whether a checkbox is checked.

Declaring Variables

Modern JavaScript gives you two ways to declare a variable:

let score = 0;
const name = "Ada";

let creates a variable you intend to change. const creates one you do not. Try to reassign a const and you get an error:

const pi = 3.14;
pi = 3.15; // Error: Assignment to constant variable.

Prefer const by default. Only use let when you know the value will change. This makes your code easier to reason about.

The Old Way: var

Before 2015, JavaScript only had var. It still works, but it has confusing rules about scope and hoisting that cause bugs. Avoid it in new code. If you see it in tutorials, translate it to let or const as you read.

Primitive Types

JavaScript has a small set of built-in value types. The five you will use constantly are:

TypeExampleUse
string"hello"Text
number42, 3.14Numbers of all kinds
booleantrue, falseYes/no values
nullnullIntentional absence of value
undefinedundefinedValue not yet assigned

You can check the type of any value with typeof:

typeof "hello"   // "string"
typeof 42        // "number"
typeof true      // "boolean"
typeof undefined // "undefined"
typeof null      // "object" (a famous bug, ignore it)

Strings

Strings hold text. You can use single quotes, double quotes, or backticks. Backticks let you insert values directly:

const first = "Ada";
const last = "Lovelace";
const full = `${first} ${last}`; // "Ada Lovelace"

This is called a template literal. Use it whenever you need to build a string from variables. It is cleaner than concatenation with +.

Numbers

JavaScript has one number type. Integers and decimals are the same. Arithmetic works as you would expect:

10 + 3    // 13
10 / 3    // 3.3333333333333335
10 % 3    // 1 (remainder)
2 ** 8    // 256 (exponent)

Booleans

A boolean is either true or false. Booleans come from comparisons and logic, which we will cover in the next chapter.

Naming Variables

Use descriptive names. userScore is better than x. isLoggedIn is better than flag. Use camelCase — the first word lowercase, each following word capitalized. This is the JavaScript convention.

Key Takeaways

  • Use const by default, let when the value changes.
  • Avoid var.
  • Strings, numbers, and booleans are the types you will use most.
  • Use template literals to build strings with variables.
  • Name variables descriptively and use camelCase.

Chapter Four

Operators and Logic

"Programs are decisions written in arithmetic."

In This Chapter

  • Arithmetic operators
  • Comparison operators, including === vs ==
  • Logical operators: &&, ||, !
  • Truthy and falsy values

Every decision your program makes comes down to a comparison. Is the score higher than ten? Is the user logged in? Is the password correct? Operators are how you ask those questions.

Arithmetic Operators

5 + 2   // 7
5 - 2   // 3
5 * 2   // 10
5 / 2   // 2.5
5 % 2   // 1 (remainder)
5 ** 2  // 25 (exponent)

The remainder operator % is more useful than it looks. Use it to test if a number is even (n % 2 === 0) or to wrap values into a range.

Comparison Operators

OperatorMeaning
===Strictly equal (same value and type)
!==Strictly not equal
>Greater than
<Less than
>=Greater than or equal
<=Less than or equal

Always use === and !==. The double-equals versions (== and !=) perform type coercion, which produces surprising results:

"5" == 5    // true  (coerced)
"5" === 5   // false (different types)

0 == false  // true
0 === false // false

The triple-equals version does not coerce. Use it always. The double-equals version is a trap.

Logical Operators

true && true    // true  (AND)
true && false   // false
true || false   // true  (OR)
!true           // false (NOT)

Use these to combine conditions:

const age = 20;
const hasLicense = true;

if (age >= 18 && hasLicense) {
  console.log("You can drive.");
}

Truthy and Falsy

Every value in JavaScript is either "truthy" or "falsy." The falsy values are:

  • false
  • 0
  • "" (empty string)
  • null
  • undefined
  • NaN (not a number)

Everything else is truthy. This matters because if (value) is a shorthand for "if value is truthy":

const name = "";
if (name) {
  console.log("Hello, " + name);
} else {
  console.log("Name is empty.");
}

Key Takeaways

  • Use === and !==, never ==.
  • && means "and," || means "or," ! means "not."
  • Know the six falsy values.
  • if (value) checks whether a value is truthy.

Chapter Five

Control Flow

"A program without conditions is a straight line with no exits."

In This Chapter

  • if, else if, and else
  • The ternary operator
  • switch statements
  • for, while, and for...of loops

Control flow is how your program decides what to do. Without it, code runs from top to bottom and stops. With it, code can branch, repeat, and skip.

if / else if / else

const score = 85;

if (score >= 90) {
  console.log("A");
} else if (score >= 80) {
  console.log("B");
} else if (score >= 70) {
  console.log("C");
} else {
  console.log("F");
}

The first true condition wins. The rest are skipped. The else block runs if nothing matched.

The Ternary Operator

When you need a value based on a condition, use the ternary:

const age = 20;
const label = age >= 18 ? "adult" : "minor";

It reads: "if age is at least 18, use 'adult', otherwise use 'minor'." Use it for simple choices. For anything more complex, use if.

switch

When you are comparing one value against many options, switch is sometimes cleaner:

const day = "Monday";

switch (day) {
  case "Monday":
  case "Tuesday":
    console.log("Start of the week.");
    break;
  case "Friday":
    console.log("Almost the weekend.");
    break;
  default:
    console.log("Just another day.");
}

Do not forget break. Without it, execution falls through to the next case.

Loops

Loops repeat code. The three you will use most are for, for...of, and while.

The for Loop

for (let i = 0; i < 5; i++) {
  console.log(i); // 0 1 2 3 4
}

The three parts are: initialize, condition, update. Use this when you know how many times to repeat.

The for...of Loop

const fruits = ["apple", "banana", "cherry"];
for (const fruit of fruits) {
  console.log(fruit);
}

Use this to iterate over arrays. It is cleaner than a counting loop.

The while Loop

let count = 0;
while (count < 5) {
  console.log(count);
  count++;
}

Use this when the number of repetitions is unknown. Be careful: if the condition never becomes false, the loop runs forever and freezes your page.

Breaking Out Early

Use break to exit a loop, and continue to skip to the next iteration:

for (const n of [1, 2, 3, 4, 5]) {
  if (n === 3) break;
  console.log(n); // 1 2
}

Key Takeaways

  • Use if/else for branching decisions.
  • Use the ternary for simple value choices.
  • Use for...of to iterate arrays.
  • Always ensure while loops can end.

Chapter Six

Functions

"A function is a named piece of behavior."

In This Chapter

  • Function declarations and expressions
  • Arrow functions
  • Parameters, arguments, and return values
  • Default parameters and rest parameters

A function is a block of code you can name and reuse. Every program larger than ten lines uses functions. They let you break a problem into pieces, name each piece, and test the pieces separately.

Declaring a Function

function greet(name) {
  return `Hello, ${name}!`;
}

console.log(greet("Ada")); // "Hello, Ada!"

The word name inside the parentheses is a parameter. The value you pass when calling the function ("Ada") is an argument. The return statement sends a value back to the caller.

Function Expressions

You can also assign a function to a variable:

const greet = function(name) {
  return `Hello, ${name}!`;
};

This is called a function expression. It behaves almost the same as a declaration but is not hoisted in the same way.

Arrow Functions

Introduced in ES6, arrow functions are a shorter syntax:

const greet = (name) => {
  return `Hello, ${name}!`;
};

// Even shorter for single expressions:
const greet = name => `Hello, ${name}!`;

Arrow functions do not have their own this, which matters in some situations (see Chapter 10). For most everyday code, they are the preferred style.

Default Parameters

function greet(name = "friend") {
  return `Hello, ${name}!`;
}

greet();        // "Hello, friend!"
greet("Ada");   // "Hello, Ada!"

Rest Parameters

Use ... to collect any number of arguments into an array:

function sum(...numbers) {
  return numbers.reduce((total, n) => total + n, 0);
}

sum(1, 2, 3, 4); // 10

Functions Are Values

In JavaScript, functions are values like any other. You can store them in variables, pass them to other functions, and return them from functions. This is what makes JavaScript flexible and is the foundation for callbacks and closures.

function run(fn) {
  fn();
}

run(() => console.log("Running!"));

Key Takeaways

  • Functions name and reuse behavior.
  • Arrow functions are shorter and do not have their own this.
  • Use default parameters for optional arguments.
  • Functions are values — pass them around freely.

Chapter Seven

Arrays

"An array is a list. Most real data is a list of something."

In This Chapter

  • Creating and reading arrays
  • Adding and removing items
  • The big three: map, filter, reduce
  • Other useful array methods

An array is an ordered list of values. Almost every real program works with arrays: a list of users, a list of products, a list of messages, a list of scores. Learn arrays well and you will unlock most of JavaScript.

Creating Arrays

const fruits = ["apple", "banana", "cherry"];
const numbers = [1, 2, 3, 4, 5];
const mixed = ["hello", 42, true, null];

Reading and Writing

fruits[0]         // "apple"
fruits[1]         // "banana"
fruits.length     // 3
fruits[0] = "pear"; // now ["pear", "banana", "cherry"]

Arrays are zero-indexed. The first item is at index 0, the second at 1, and so on.

Adding and Removing

const arr = [1, 2, 3];

arr.push(4);      // [1, 2, 3, 4]      add to end
arr.pop();        // [1, 2, 3]         remove from end
arr.unshift(0);   // [0, 1, 2, 3]      add to start
arr.shift();      // [1, 2, 3]         remove from start

The Big Three: map, filter, reduce

These three methods are the heart of modern JavaScript array work. Learn them deeply.

map

map transforms each item and returns a new array of the same length:

const nums = [1, 2, 3, 4];
const doubled = nums.map(n => n * 2);
// [2, 4, 6, 8]

filter

filter keeps items that pass a test:

const nums = [1, 2, 3, 4];
const evens = nums.filter(n => n % 2 === 0);
// [2, 4]

reduce

reduce combines all items into a single value:

const nums = [1, 2, 3, 4];
const total = nums.reduce((sum, n) => sum + n, 0);
// 10

The second argument (0) is the starting value. Without it, reduce uses the first item as the starting value, which is often fine but sometimes confusing.

Other Useful Methods

MethodWhat it does
findReturns the first matching item
someReturns true if any item matches
everyReturns true if all items match
includesReturns true if array contains a value
sortSorts the array (mutates it)
reverseReverses the array (mutates it)
joinCombines items into a string
sliceReturns a copy of part of the array
concatCombines arrays into a new one

Key Takeaways

  • Arrays are zero-indexed lists.
  • map transforms, filter selects, reduce combines.
  • Learn these three and you can solve most array problems.
  • Most array methods return a new array; a few mutate the original.

Chapter Eight

Objects

"An object is a collection of named values."

In This Chapter

  • Creating and reading objects
  • Methods on objects
  • Destructuring
  • The spread operator

An object is a collection of key-value pairs. Where arrays are ordered lists, objects are named collections. If you want to describe a person, you do not use an array of values; you use an object with named properties.

Creating Objects

const user = {
  name: "Ada",
  age: 36,
  isAdmin: true,
};

Reading and Writing

user.name          // "Ada"
user["age"]        // 36

user.age = 37;     // update
user.email = "ada@example.com"; // add new property

Use dot notation when you know the property name. Use bracket notation when the name is stored in a variable or contains unusual characters.

Methods

Functions stored on objects are called methods:

const user = {
  name: "Ada",
  greet() {
    return `Hello, ${this.name}!`;
  },
};

user.greet(); // "Hello, Ada!"

Notice this.name. Inside a method, this refers to the object the method was called on. We will cover this in detail in Chapter 10.

Destructuring

Extract properties into variables in one line:

const user = { name: "Ada", age: 36 };
const { name, age } = user;

console.log(name); // "Ada"
console.log(age);  // 36

The Spread Operator

Copy or merge objects without mutating the original:

const user = { name: "Ada", age: 36 };
const updated = { ...user, age: 37 };
// { name: "Ada", age: 37 }

This creates a new object. The original user is unchanged. This pattern is everywhere in modern JavaScript, especially in React.

Objects Inside Arrays

Most real data looks like an array of objects:

const users = [
  { name: "Ada", age: 36 },
  { name: "Alan", age: 41 },
  { name: "Grace", age: 45 },
];

const names = users.map(u => u.name);
// ["Ada", "Alan", "Grace"]

This pattern — an array of objects, transformed with map, filter, and reduce — is the bread and butter of JavaScript development.

Key Takeaways

  • Objects store named values.
  • Use dot notation to read and write properties.
  • Destructuring extracts properties cleanly.
  • The spread operator copies without mutating.
  • Real data is usually an array of objects.

Chapter Nine

Scope, Hoisting, and Closures

"Where a variable lives determines what it can see."

In This Chapter

  • Global, function, and block scope
  • How hoisting works
  • What a closure is and why it matters

These three ideas are where most beginners either build a solid mental model or develop bad habits that haunt them for years. Slow down here. Read this chapter twice.

Scope

Scope is the area of code where a variable is accessible. JavaScript has three kinds:

Global Scope

Variables declared outside any function or block are global. They are accessible everywhere. Avoid them. Global variables create confusion and conflicts.

const globalVar = "I am everywhere";

Function Scope

Variables declared inside a function are only accessible inside that function:

function greet() {
  const message = "Hello";
  console.log(message); // works
}

greet();
console.log(message); // Error: message is not defined

Block Scope

Variables declared with let and const inside a block ({ }) are only accessible in that block:

if (true) {
  let inside = "here";
  console.log(inside); // works
}

console.log(inside); // Error

This is one reason to prefer let and const over var. var ignores block scope, which leads to bugs.

Hoisting

JavaScript moves declarations to the top of their scope before running code. This is called hoisting. It is why this works:

console.log(greet()); // "Hello!"

function greet() {
  return "Hello!";
}

But it also causes strange behavior with var:

console.log(x); // undefined (not an error!)
var x = 5;

With let and const, the variable exists but cannot be used before declaration. This is called the "temporal dead zone," and it is a good thing. It catches mistakes earlier.

Closures

A closure is a function that remembers the scope where it was created, even after that scope has finished running.

function counter() {
  let count = 0;
  return function() {
    count++;
    return count;
  };
}

const next = counter();
next(); // 1
next(); // 2
next(); // 3

Notice that count persists between calls. The inner function closes over the variable count and keeps it alive.

Closures are everywhere. They power module patterns, event handlers, callbacks, and private state. If you understand closures, you understand a huge part of JavaScript.

Key Takeaways

  • Scope determines where variables are visible.
  • Prefer let and const over var to avoid hoisting surprises.
  • A closure is a function that remembers its birth scope.
  • Closures enable private state and callbacks.

Chapter Ten

The this Keyword

"this is not where the function is written. It is how the function is called."

In This Chapter

  • What this means in different contexts
  • How arrow functions differ
  • How to avoid this confusion

The keyword this confuses almost every beginner. The confusion comes from assuming this refers to the function itself. It does not. this refers to the object the function was called on. And if there is no such object, this is either the global object (in non-strict mode) or undefined (in strict mode).

In a Method

const user = {
  name: "Ada",
  greet() {
    return `Hello, ${this.name}`;
  },
};

user.greet(); // "Hello, Ada"

When you call user.greet(), this inside greet refers to user.

In a Plain Function

function show() {
  console.log(this);
}

show(); // in browsers: the global window object

When a function is called without an object, this is the global object. This is almost never what you want, which is why modern code avoids relying on this in plain functions.

In Arrow Functions

Arrow functions do not have their own this. They use the this from the surrounding scope:

const user = {
  name: "Ada",
  greet: () => {
    return `Hello, ${this.name}`;
  },
};

user.greet(); // "Hello, undefined" — this is not user

This is why arrow functions are usually the wrong choice for object methods. Use a regular function or the method shorthand when you need this.

How to Avoid Confusion

  • Use method shorthand when defining object methods.
  • Use arrow functions for callbacks that do not need this.
  • When in doubt, avoid this and pass values as parameters.

Key Takeaways

  • this depends on how a function is called.
  • Arrow functions inherit this from the surrounding scope.
  • Use method shorthand for object methods.
  • When confused, avoid this and pass parameters.

Chapter Eleven

The Event Loop

"JavaScript is single-threaded, but it never has to wait."

In This Chapter

  • Why JavaScript can do one thing at a time
  • How the call stack works
  • What the event loop does
  • Why setTimeout does not block

JavaScript runs on a single thread. That means it can only do one thing at a time. And yet a webpage can load data from a server, respond to clicks, and animate a button — all at once. How?

The answer is the event loop. JavaScript does not actually do multiple things at once. It does one thing, finishes, then picks up the next thing from a queue. The browser handles the waiting.

The Call Stack

When you call a function, it goes on the call stack. When it returns, it comes off. Only the function on top of the stack is running. This is straightforward and synchronous.

Web APIs

When you call setTimeout, fetch, or addEventListener, the browser takes over. It sets a timer or waits for a network response in the background. JavaScript itself is free to keep running.

The Event Loop

When the browser finishes a task, it puts the callback into a queue. The event loop checks: "Is the call stack empty?" If yes, it takes the next item from the queue and runs it.

This is why this code does not print in the order it appears:

console.log("1");

setTimeout(() => {
  console.log("2");
}, 0);

console.log("3");

// Output: 1, 3, 2

Even with a delay of 0 milliseconds, setTimeout pushes its callback to the queue. The event loop waits until the call stack is empty. Both "1" and "3" print first.

Microtasks vs Tasks

Promises use a separate queue called the microtask queue. Microtasks run before the next task. This matters when you mix promises and timers, which we will see in Part V.

Key Takeaways

  • JavaScript runs on a single thread.
  • The event loop lets it handle asynchronous work without blocking.
  • setTimeout(fn, 0) still waits for the stack to clear.
  • Promises use the microtask queue, which runs before timers.

Events

"An event is the browser telling your code that something happened."

In This Chapter

  • Adding event listeners
  • Common event types
  • Event bubbling
  • preventDefault

Events are how users talk to your code. A click, a key press, a form submission, a page load — each is an event. You attach a function, called a listener, and the browser calls it when the event happens.

Adding a Listener

const button = document.querySelector("#myButton");

button.addEventListener("click", () => {
  console.log("Clicked!");
});

Common Events

EventWhen it fires
clickMouse click
dblclickDouble click
inputEvery keystroke in an input
changeValue committed (blur or enter)
submitForm submitted
keydownKey pressed
mouseoverMouse enters an element
loadPage or resource loaded

The Event Object

Every listener receives an event object with information about what happened:

button.addEventListener("click", (event) => {
  console.log(event.target); // the element clicked
});

Event Bubbling

Events start at the target element and bubble up to its parents. This means a listener on a parent can catch events from children:

document.querySelector("ul").addEventListener("click", (event) => {
  if (event.target.tagName === "LI") {
    console.log("You clicked:", event.target.textContent);
  }
});

This is called "event delegation," and it is a powerful pattern. Instead of adding a listener to every item, add one to the parent.

preventDefault

Some events have default behavior. Links navigate. Forms submit and reload. To stop that:

form.addEventListener("submit", (event) => {
  event.preventDefault();
  // handle the form in JavaScript
});

Key Takeaways

  • Use addEventListener to respond to events.
  • The event object carries information about what happened.
  • Events bubble up — use delegation for lists.
  • Use preventDefault to stop default browser behavior.

Forms and Input

"Forms are how users give your application data."

In This Chapter

  • Reading input values
  • Validating input
  • Handling form submission
  • Storing data locally

Forms are where JavaScript meets real user data. Reading inputs, validating them, and responding to submission is one of the most common tasks in web development.

Reading Input

const input = document.querySelector("#name");
const value = input.value;

value is always a string. If you need a number, convert it:

const age = Number(input.value);

Validating Input

if (input.value.trim() === "") {
  console.log("Name cannot be empty.");
  return;
}

Always validate on the client for user experience. Always validate on the server for security. Never trust user input.

Handling Submission

const form = document.querySelector("#myForm");

form.addEventListener("submit", (event) => {
  event.preventDefault();

  const name = form.querySelector("#name").value.trim();
  const email = form.querySelector("#email").value.trim();

  if (!name || !email) {
    alert("Please fill in all fields.");
    return;
  }

  console.log("Submitted:", { name, email });
});

Local Storage

Store small amounts of data in the browser so it survives a refresh:

localStorage.setItem("username", "Ada");
const saved = localStorage.getItem("username"); // "Ada"
localStorage.removeItem("username");

Local storage only stores strings. To store objects, convert with JSON.stringify and JSON.parse:

const user = { name: "Ada", age: 36 };
localStorage.setItem("user", JSON.stringify(user));

const stored = JSON.parse(localStorage.getItem("user"));
console.log(stored.name); // "Ada"

Key Takeaways

  • Read input values with .value.
  • Always validate user input.
  • Use preventDefault to handle forms in JavaScript.
  • Use localStorage for small persistent data.

Asynchronous JavaScript

Callbacks, promises, async/await, and fetch — how to work with time, waiting, and the network.

Chapter Fifteen

Callbacks and Promises

"Asynchronous code is code that finishes later."

In This Chapter

  • Why asynchronous code exists
  • Callbacks and their problems
  • Promises and how to chain them

Some operations cannot finish immediately. Loading data from a server takes time. Reading a file takes time. Waiting for a timer takes time. Asynchronous JavaScript is how you write code that does not freeze while waiting.

Callbacks

A callback is a function passed to another function to run later:

setTimeout(() => {
  console.log("This runs after one second.");
}, 1000);

Callbacks work, but nesting them becomes painful:

getUser(id, (user) => {
  getPosts(user.id, (posts) => {
    getComments(posts[0].id, (comments) => {
      console.log(comments);
    });
  });
});

This is called "callback hell." Promises were invented to solve it.

Promises

A promise represents a future value. It is either pending, fulfilled, or rejected. You attach handlers with .then() and .catch():

fetch("https://api.example.com/data")
  .then(response => response.json())
  .then(data => console.log(data))
  .catch(error => console.error(error));

Each .then() returns a new promise, so you can chain them. The .catch() at the end handles errors from any step.

Creating a Promise

function wait(ms) {
  return new Promise((resolve) => {
    setTimeout(resolve, ms);
  });
}

wait(1000).then(() => console.log("Done waiting"));

You rarely create promises yourself. Most come from browser APIs like fetch.

Key Takeaways

  • Asynchronous code avoids freezing the page.
  • Callbacks work but nest badly.
  • Promises are chainable and easier to read.
  • Use .catch() to handle errors.

Chapter Sixteen

async/await and fetch

"async/await is promises wearing a friendlier coat."

In This Chapter

  • Writing async functions
  • Using await
  • Error handling with try/catch
  • Making real HTTP requests

Promises work, but chains of .then() still read awkwardly. async/await lets you write asynchronous code that reads like synchronous code. It is now the standard way to write asynchronous JavaScript.

async Functions

Add the word async before a function and it always returns a promise:

async function greet() {
  return "Hello";
}

greet().then(msg => console.log(msg)); // "Hello"

await

Inside an async function, use await to pause until a promise resolves:

async function loadData() {
  const response = await fetch("https://api.example.com/data");
  const data = await response.json();
  console.log(data);
}

Read it as: "wait for the fetch to finish, then wait for the JSON, then log it." It reads like synchronous code but does not block the page.

Error Handling

Use try/catch around awaited code that might fail:

async function loadData() {
  try {
    const response = await fetch("https://api.example.com/data");
    if (!response.ok) {
      throw new Error(`HTTP error: ${response.status}`);
    }
    const data = await response.json();
    console.log(data);
  } catch (error) {
    console.error("Failed to load data:", error);
  }
}

This is the pattern you will use in almost every real application.

A Complete Example

async function getUser(id) {
  try {
    const response = await fetch(`https://api.example.com/users/${id}`);
    if (!response.ok) throw new Error("User not found");
    const user = await response.json();
    return user;
  } catch (error) {
    console.error(error);
    return null;
  }
}

const user = await getUser(1);
console.log(user);

Key Takeaways

  • async/await is cleaner than promise chains.
  • Always wrap awaited code in try/catch.
  • Check response.ok before parsing JSON.
  • This is the standard pattern for real applications.

Chapter Nineteen

How to Practice

"Knowledge comes from reading. Skill comes from doing."

This chapter matters more than any resource list. Learning to code is not about collecting information. It is about building skill, and skill comes from deliberate practice.

  1. Code every day. Even 30 minutes beats 5 hours once a week. Consistency builds muscle memory.
  2. Build projects, not tutorials. After each tutorial, close it and rebuild the same thing from memory. This is where the real learning happens.
  3. Struggle first. Try to solve a problem for 20–30 minutes before looking up the answer. The struggle is the learning.
  4. Read error messages. They tell you the file, the line, and often the exact problem. Most beginners ignore them and lose hours.
  5. Use the console. console.log() is not a beginner tool. Professionals use it every day.
  6. Teach someone else. Explaining closures or this out loud exposes the gaps in your understanding.
  7. Revisit old projects. Every few weeks, return to something you built and improve it. You will be surprised how much you have learned.

  • Consistency beats intensity.
  • Build, do not just watch.
  • Struggle before looking up the answer.
  • Teach to test your understanding.
Chapter Twenty

Common Pitfalls

"The mistakes are predictable. Knowing them in advance saves months."

Every beginner makes some of these mistakes. The point is not to avoid them entirely but to recognize them quickly and correct course.

  • Tutorial hell. Watching videos endlessly without building anything yourself. Break the cycle by building after every tutorial.
  • Skipping fundamentals. Jumping to React before understanding JavaScript. Frameworks are easier when the language is solid.
  • Memorizing instead of understanding. You do not need to memorize syntax. You need to understand concepts. Syntax is searchable; understanding is not.
  • Fear of breaking things. You cannot break your computer by writing JavaScript. Experiment freely. Refresh the page if something goes wrong.
  • Comparing yourself to others. Everyone learns at a different pace. The only useful comparison is to yourself a month ago.
  • Chasing every new tool. You do not need the newest framework. Learn the language first.
  • Giving up too early. The first three months are the hardest. Push through. It gets easier.

  • Tutorial hell is real. Build to escape it.
  • Fundamentals first. Frameworks later.
  • Understanding beats memorization.
